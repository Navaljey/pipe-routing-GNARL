### 핵심 제약 — 서포트는 심판이 배치한다 (S1-6 회신)

> V3 는 서포트를 출력하지 않고 **배관 배치로 묶임을 유도**한다

묶임 판정 기준이 **명시적·결정적·동결**됐다 (계약 §b):

```
같은 바닥·천장 면 · 수평 평행 · 축 ±250 mm
지지면 쪽 표면 높이 차 ≤ 50 mm · L1·L2 표 범위
다리 사이 간섭 없음 · 묶은 무게 < 개별 합일 때만 · 좌표 순서 탐욕
```

**이것이 V3 설계를 크게 단순화한다.**

1. **묶임 조건은 학습 대상이 아니다 — 계산 대상이다.** 술어가 결정적이고
   공개돼 있으므로, "묶임 가능 회랑"은 `placed` 에서 결정적으로 유도되는
   **입력 특징**이다. V3 가 추측할 것이 없다.
2. **조율 망이 결정할 것은 하나뿐** — "그 묶음을 쫓기 위해 길이·꺾임을
   지불할 가치가 있는가".
3. **유인이 단조다.** "묶은 무게 < 개별 합일 때만" 이므로 심판이 V3 에게
   불리하게 묶는 일이 없다. 묶임 자체는 항상 이득이고, 비용은 거기 가려고
   지불하는 길이·꺾임뿐. 학습 난이도가 크게 낮아진다.

- 0 으로 채운 채널이 1·2단계 모방 학습을 방해하지 않는지 (소규모 A/B)

**결론: 3단계 보상은 검증기 값을 직접 쓴다.** 라우터 추정-검증기 간극 문제가

#### ⚠️ 단 보상은 `J_total` 단일 스칼라로 받는다 — 배관별 J 를 쓰지 않는다

회신의 *"D 묶음은 매 호출 **전체 재수행**(탐욕 연쇄 때문)"* 이 중요하다.

탐욕 연쇄가 있다는 것은, 배관 P 를 추가하면 **다른 배관의 `kg_share` 가
바뀔 수 있다**는 뜻이다. P 가 Q 의 묶음 상대 R 을 가져가고, Q 는 S 와 묶이고,
S 는 T 와… 묶임 조건이 축 ±250 mm 라 공간적으로는 국소하지만 **연쇄는 전파된다.**

| 보상 형태 | 판정 |
|---|---|
| **`J_total` 단일 스칼라** | ✅ 채택. 연쇄에 영향받지 않는다 |
| 배관별 J (`kg_share`) 를 배관별 보상으로 | ❌ 신용 할당 왜곡 — 배관 자신이 잘해서가 아니라 남이 묶음을 가져가서 값이 변한다 |

`kg_share` 는 **진단용**으로만 쓴다 (어느 배관이 병합 이득을 받았는지 분석).

> skeleton 이 "귀속은 **회계 규약**" 이라고 한 것과 같은 결론이다.

> v2 참고치: success_rate −5%p 이내, length_ratio +10% 이내
> v2 측정 노이즈 바닥: 0.0135 (= 1/75). 합격 여유는 이보다 커야 한다.

**실측 분포를 본 뒤에 정한다.** 다만 "실측 후 정한다"를 명시해두지 않으면
v2 의 L-A3'처럼 끝까지 미뤄진다.

### D-b. 2단계 기울기 측정 방법

- 맵 크기를 몇 점에서 재는가 (최소 3점)
- 크기 축 — 셀 수? 변 길이? 자유 공간 부피?
- 회귀선 기울기 vs 로그-로그 기울기
- 합격 여유 — 노이즈 폭보다 커야 한다

### D-d. "큰 맵 × 다중 배관" 공백  *(기한: E2 생성 전)*

- 2단계 = 큰 맵 × **단일** (E2) / 3단계 = 보통 맵 × **다중** (E1 밀집)
- → **큰 맵 × 다중**을 보는 단계가 없다

3단계에서 라우터가 freeze 되므로 큰 맵 능력은 2단계에서 검증됐다고 볼 수도 있으나,
조율 망이 큰 맵에서 같은 성능을 내는지는 별개다. 배관 수가 같아도 맵이 커지면
경합 구조가 달라진다.

정할 것: (a) 3단계 평가에 추가 / (b) 4단계 E3 에서 함께 / (c) 범위 밖.

### D-e. 실제 블록 데이터 — 대표성 확인 수단  *(기한: E2 생성 전)*

- E1 "수작업" 세트가 실제 블록 유래인지 가상 구성인지 명시
- 실제 블록 데이터 확보 가능 여부, 몇 개 블록 분량
- **대표성 판정 지표** — 장애물 밀도 분포? 배관 수? start-goal 거리 분포? 굴곡도?
- 합격선 — 생성 시나리오가 실제 블록 분포를 어느 정도 덮어야 하는가
- 실제 블록을 최종 평가 전용으로 쓸 것인가, 일부를 학습에 넣을 것인가 (누수 방지)

이것이 없으면 모든 성능 수치가 "우리가 만든 시나리오에서만 잘한다"로 귀결된다.

### D-f. 모방 → 강화학습 전환의 실측 근거

경계는 "다중 배관"으로 확정. 남은 것: **"A\* 라벨 생성이 너무 비싸다"의 실측 기준.**
A\* 1회 계산이 몇 초를 넘으면 오프라인 라벨 생성을 포기하는가. 2단계 실측 필요.

## 4. skeleton 쪽 남은 확인 1건 (급하지 않음 — 다음 교신에 묶어 보낸다)

**블록 쌍 라벨 생성 시점.**

회신: *"S1-6b·S1-7 은 **단일 블록** A\* 결과를 바꾸지 않음"*

E1 에는 **블록 쌍**이 포함된다 (경계 관통점). 그런데 위 문장은 단일 블록에
대한 보장이다. 블록 쌍 시나리오 자체는 S1-7 에서 만들어지므로:

- 단일 블록 라벨 = S1-6 병합 직후 생성 가능 ✅
- **블록 쌍 라벨 = S1-7 이후**로 보인다 → 1단계 라벨 생성이 두 번에 나뉜다

맞는지 확인이 필요하다. 맞다면 1단계 학습을 (a) 단일 블록만으로 먼저 돌리고
블록 쌍을 나중에 추가 학습 / (b) S1-7 까지 기다려 한 번에 — 중 선택해야 한다.

전용 교신을 열 만큼 급하지는 않다. S1-6 병합 공지 때 함께 묻는다.
