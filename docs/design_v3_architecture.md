## 0. 한 줄

**신경망이 경로를 내지 않는다.** 경로는 탐색이 내고, 실현 가능성은 Layer 0 마스크와
확정 단계가 보장한다. 신경망은 두 자리에만 들어간다 — ① 탐색을 **빠르게** 하는
우선순위, ② 다중 배관을 **잘** 놓는 가격·순서·묶음 판단.

이 구조의 가장 큰 효과는 **1단계 승리 조건 3개 중 2개가 학습 결과가 아니라 구조적
보장으로 바뀐다**는 점이다 (§2.3). 대신 새 위험이 하나 생긴다 — **협상 반복이
계약 탐색 예산 2²² 을 먹는다** (§3 D-s, §5-1).

## 1. 판단 근거

> §1 전체는 **소유자 지시 §1 의 요약**이다. V3 가 새로 주장한 것이 아니다.
> 문헌 인용은 지시가 준 것을 그대로 쓰고, V3 가 보탠 것은 출처를 밝힌다.

### 1.1 신경망으로 A\* 를 학습할 수 있는 근거

**근거 — 알고리즘 정렬 (algorithmic alignment).**

| 출처 | 내용 |
|---|---|
| Xu et al. 2020 (ICLR, *What Can Neural Networks Reason About?*) | 망 구조가 대상 알고리즘의 구조와 맞으면 표본 복잡도가 낮아진다 |
| Veličković et al. 2020 (ICLR, *Neural Execution of Graph Algorithms*) | GNN 메시지 전달 1회 = Bellman-Ford 완화 1단계. 층 수가 경로 홉 수 이상이면 최단거리를 **정확히 표현**할 수 있다 |

### 1.2 한계 3가지

| | 한계 | V3 에서 의미하는 것 |
|---|---|---|
| **1** | "표현 가능" 이지 **"학습 보장" 이 아니다.** 고정 깊이 망은 학습보다 긴 경로·큰 맵에서 일반화가 약하다 | **2단계(E2) 의 위험이 바로 이것이다.** 대책은 D-r |
| **2** | 보편 근사 정리가 직접 적용되지 않는다 — 경로는 입력에 대해 **불연속인 이산 출력**이다 | 망이 경로를 직접 내는 설계를 쓰지 않는 이유 |
| **3** | 망이 경로를 직접 내면 **충돌·꺾임·구배·서포트 규칙을 지킨다는 보장이 없다** | §0 의 원칙. 실현 가능성은 탐색·확정이 맡는다 |

### 1.3 핵심 — 1단계에서 품질 우위는 원리적으로 불가능하다

같은 그래프 위에서 **A\* 는 이미 J 최적**이다 (D40). 따라서

```
A* 모방이 주는 이득 = 속도.  품질 이득은 0 이다 (같은 그래프에서는).
```

품질 이득이 나올 자리는 두 곳뿐이고, **둘은 분리해 보고한다** (지시 §1, D-v).

| 출처 | 어디서 | 비고 |
|---|---|---|
| **(a) 다중 배관 조정** | 3단계 | NP-hard 구간. 여기가 본전이다 |
| **(b) 표현 해상도** | 미정 | 격자 손실 약 **5%** (R4 인용). **V3 는 현재 이것에 대한 계획이 없다** → §5-5 |

> ⚠️ **이것이 §7.5 "천장 경고" 를 대체한다.** 1단계를 "A\* 를 얼마나 재현하나" 로
> 본 §7.5 의 서술은 더 약하다. 정확히는 **"A\* 와 같은 품질을 보장받은 상태에서
> 얼마나 빨라지나"** 다. 재현율이 아니라 확장 수가 지표다.

### 1.4 다중 배관 방안 비교

전체 문제(여러 배관을 겹치지 않게 놓으면서 ΣJ 최소)는 **NP-hard** 다
(서로소 경로 문제 계열).

| | 방식 | 성질 | 판정 |
|---|---|---|---|
| **(b)** | **순차 배치**, 앞 배관 = 단단한 장애물 | 항상 실현 가능 · 결정적 | **= skeleton 기준선 (D50).** 이것만 하면 기준선과 같아진다 |
| **(a)** | 각자 최단 경로 → **사후** 간섭 해소 | 기하를 국소적으로 밀어내면 꺾임·서포트 규칙이 **연쇄로 깨진다** | ❌ **쓰지 않는다** |
| **(a′)** | **협상 기반 재라우팅** (PathFinder, 라그랑주 완화) | 간섭 제약을 **가격**으로 완화 | ✅ **채택** |

**(b) 의 약점 — 전부 실측·심판 확인된 것이다.**

- 탐욕이라 **순서에 의존**한다
- 앞 배관이 뒤 배관의 단자·서포트 자리를 막는다 — D59·D90 이후에도 **R7 18건 잔존**
- **랙을 의도적으로 만들지 못한다**
- 밀집 50 완전 성공 **0/5**

**(a′) 협상 루프의 형태**

```
간섭 제약을 가격으로 완화
   ↓
배관별 독립 라우팅 (겹침 허용, 겹친 공간에 가격)
   ↓
붐비는 곳 가격 상승 (현재 혼잡 + 이력 비용)
   ↓
반복
   ↓
마지막에 단단한 장애물로 확정 (= (b) 순차 확정)
```

문헌: PathFinder = McMurchie & Ebeling, FPGA'95, *negotiated congestion* (FPGA 배선).
구조가 거의 같다 — 겹침을 허용하고 가격으로 밀어낸다.

**(a′) 의 이점 — 참고 하한이 생긴다.**

가격 0 일 때 `Σ(배관별 단독 최적 J)` 는 전체 최적의 **참고 하한**이 된다.
기준선 대비 곡선만 보던 것에 **절대 기준**이 하나 붙는다.

> ⚠️ **단서 (지시가 명시):** D 형식 공유 서포트(D81·D82)가 있으면 묶음이 무게를
> 줄이므로 **엄밀한 하한이 아니다.** `Σ 단독 J` 보다 좋은 해가 존재할 수 있다.
> **그 차이가 곧 R7(랙 형성) 이득의 자리다.**

**가장 중요한 한 줄 (지시 §1-2 마지막):**

> 간섭은 **밀어내는 힘**만 준다. **서포트 공유라는 끌어당기는 힘**을 목적에 넣어야
> 랙이 생긴다.

→ 협상만 구현하면 배관이 서로 멀어지기만 한다. 끌어당김 항(D-t)이 없으면
R7 은 안 풀린다.

## 2. 목표 구조

### 2.1 3층

| 층 | 방법 | 학습 역할 | 보장 |
|---|---|---|---|
| **단일 배관 라우터** | **A\* + 포컬 탐색.** admissible `h` 로 `f_min` 유지, `FOCAL = {f ≤ (1+ε)·f_min}` 안을 **학습 점수 순으로** 확장 | **신경망 ①** = 학습 휴리스틱 / 확장 우선순위 | **그래프 위 최적 J × (1+ε) 이하.** 망 품질과 무관하게 하한 유지, 좋으면 빨라짐 |
| **다중 배관 조정** | **(a′) 협상·가격 반복** → 마지막에 **(b) 순차 확정** (단단한 장애물 + 단자·부재 예약) → skeleton 검증기 `Session`(D85 증분)으로 채점 | **신경망 ②** = 가격 갱신 · 순서 · **랙 형성**(어느 배관을 나란히 묶을지) | NP-hard 구간 (R2·R7). 보장 없음 |
| **확정·채점** | **skeleton 검증기** | 없음 | 계약 §(b) — **변경 금지** |

포컬 탐색 문헌: `A*_ε` = Pearl & Kim 1982. 학습된 포컬 우선순위 =
Bhardwaj et al. CoRL 2017 *Learning Heuristic Search via Imitation* 계열.
`추측:` 후자는 기억에 의한 인용이다. 설계에 쓰기 전에 원문 확인이 필요하다.

### 2.2 원칙

```
1. 신경망은 경로를 직접 출력하지 않는다. 실현 가능성은 탐색과 확정이 보장한다.
2. 탐색 중에는 다른 배관을 벌점 붙은 "부드러운 장애물" 로 본다.
   확정 단계에서만 "단단한 장애물" 로 본다.
3. 협상은 라우터를 수백 번 호출한다 — 신경망 ① 의 속도 이득이
   여기서 실제 가치가 된다.
4. D8(GNARL 역할) = "둘 다, 역할 분담" — 단일 경로 쪽은 속도, 조정 쪽은 품질.
```

### 2.3 이 구조가 걷어내는 기존 실패 위험

**1단계 승리 조건 3개 중 2개가 구조적 보장이 된다.**

| 계약 §(e2) 1단계 조건 | 지금까지 | 이 구조에서 |
|---|---|---|
| **J ≤ A\* +1%** | 학습 결과에 달려 있었다 | **ε ≤ 0.01 로 구조적 보장.** 포컬 탐색의 정의다 |
| **성공 수 같음** | 학습 결과에 달려 있었다 | **구조적 보장.** `FOCAL ⊆ OPEN` 이고 가지치기를 하지 않으므로 완전성이 A\* 와 같다 |
| **확장 수(시간) 감소** | 학습 결과 | **학습 결과.** ← **1단계의 유일한 실제 과제** |

**RL 병리 4건이 1·2단계에서 사라진다** — 1단계에 MDP 가 없기 때문이다.

| 기존 Lock / 경고 | 이 구조에서 |
|---|---|
| **S1-L1** 1단계 수렴 붕괴 (0.271 → 0.00) | **적용 안 됨.** PPO 가 없다 |
| **τ 붕괴** (§19-2) | **적용 안 됨.** softmin 샘플링이 없다. τ 는 3단계로 (S1-N1 그대로) |
| **h 드리프트** (§19-2) | **적용 안 됨.** h 는 지도 회귀로만 학습·고정된다 |
| **G3-L1 수렴 천장 0.40~0.45** | **적용 안 됨.** "목표에 닿는가" 는 A\* 가 보장한다. 천장은 *도달률* 의 천장이었다 |
| **데드락** (§4 STAY, §16-5 `fail_cost`, 종단 처리) | **실패 양식이 아니다.** A\* 에서 막다른 길은 닫힌 노드이고 탐색이 되돌아간다 |
| **G3-N7** 벤딩 마스크가 탐색 장치 | **1·2단계에서 무의미.** 체계적 탐색에는 탐색 보조가 필요 없다. 마스크는 후계자 생성에서 Layer 0 으로만 작동 |

> ⚠️ **이 표는 "쉬워졌다" 는 뜻이 아니다.** 위험이 **옮겨간** 것이다.
> 새 위험은 §7 에 모았고, 그중 **확장 예산(D-s)** 이 가장 크다.

### 2.4 자산 승계 — 무엇이 살고 무엇이 역할을 잃는가

| 자산 | 상태 |
|---|---|
| `h_net` 사전학습 (val MAE **1.51 kg** vs 맨해튼 2.88 / octile3d 3.50, §19-5) | ✅ **그대로 승계.** 이제 **포컬 우선순위**가 된다. 1단계의 본체 |

| 배치 h 평가 `build_obs_batch()` (§6-2, GPU batch(27)≈batch(1)) | ✅ 승계. 포컬 탐색도 후계자 26개를 한 번에 점수 매긴다 |

| 엘보 청구 규칙 (§16-5) | ✅ 그대로 (단 J 정본은 검증기) |
| `v3/guards.py` (D-m) | ✅ 그대로. 라벨 출처·시드 범위 하드 스톱 |
| D-n §2 `ΔJ` bias 주입 지점 | ✅ **승계 — 가격의 주입 지점이 된다** (§4-2) |
| **MaskablePPO · PBS Φ · τ · `ent_coef` · `fail_cost` · 종단 처리** | ⏸ **1·2단계에서 역할 없음.** 3단계 신경망 ② 가 RL 이면 그때 쓴다 (D-u) |
| `GNARL_OBS_DIM = 2155` (이웃 27 전개) | ⏸ **불필요해질 수 있다.** 포컬 탐색은 OPEN/FOCAL 이 후보를 공급한다 → D-p |
| `step1_train.ipynb` | ❌ **노선이 두 번 바뀌었다.** 재사용은 환경·마스크·h 사전학습 셀에 한정 |
| §16·§19 실측값 | ✅ **전부 유효.** 폐기된 것은 노선이고 측정값이 아니다 |

| 단계 | 이 구조에서 |
|---|---|

## 3. 결정 후보 (확정은 소유자)

기존 번호 체계(D-a ~ D-o)를 이어 **D-p ~ D-w** 를 붙인다.
각 항목에 **권고 · 근거 · 대안 · 위험**을 적는다.

### D-p. 신경망 ① 입출력

| | |
|---|---|
| **권고** | **출력 = 남은 비용 추정 `ĥ(s)` 하나.** 포컬 우선순위는 `ĥ` 로 정렬해 쓴다 |
| **근거** | ① `h_net` 사전학습 자산이 그대로 쓰인다 (val MAE 1.51 kg) ② 라벨이 skeleton A\* 의 cost-to-go 로 **이미 정의돼 있다** ③ 지도 회귀라 학습이 안정적이다 — §19 의 두 붕괴 기전이 모두 RL 산물이었다 |
| **대안** | **(ii) 확장 우선순위를 직접 학습** (learning-to-rank). 포컬 안에서 "어느 것을 먼저 열까" 는 `ĥ` 순서와 꼭 같지 않다 — 이론상 (ii) 가 상한이 더 높다 |
| **위험** | (i) 은 `ĥ` 가 좋아도 확장 수가 덜 줄 수 있다. **1단계 결과가 미달이면 (ii) 로 간다** |

**입력 특징 (지시 §3-1 이 준 목록)**

```
상태 : 노드 · 방향 · run · bend · 마스크 · 중력관 h · 서포트 u
국소 : 장애물 · 놓인 배관 정보
```

기존 76차원(§8)과 비교하면 **중력관 `h` 와 서포트 `u` 가 새로 들어온다.**

| | |
|---|---|
| **권고** | 76차원을 **기반으로 하고 뒤에 붙인다.** 이웃 27 전개(2155차원)는 **쓰지 않는다** |
| **근거** | 포컬 탐색에서는 OPEN/FOCAL 이 후보를 공급하므로 관측에 이웃을 실을 필요가 없다. 2155차원은 "정책이 환경을 못 본다" 는 RL 제약 때문에 있었다 |

#### ⚠️ D-s 의 실제 위험 — 계약 탐색 예산 2²²

협상은 라우터를 **배관 수 × 반복 수** 만큼 부른다. 밀집 50 에서:

| 반복 R | 라우터 호출 | **호출당 허용 확장** (2²² 가 시나리오 단위일 때) |
|---|---|---|
| 5 | 250 | 16,777 |
| 10 | 500 | 8,388 |
| **20** | **1,000** | **4,194** |
| 50 | 2,500 | 1,677 |

비교 대상: 50×50×20 격자의 A\* **상태** 공간은
`50,000 칸 × 26 방향 × 7 run` ≈ **9.1 M 상태**이고, 경로 길이는 대각 기준 약 **74칸**이다.
R=20 이면 호출당 4,194 확장 = 상태 공간의 **0.05%** 안에서 끝내야 한다.

```
→ 신경망 ① 의 속도 이득이 "있으면 좋은 것" 이 아니라 협상의 전제 조건이다.
→ 2²² 의 단위(시나리오당 / 배관당 / 호출당)를 모르면 R 을 정할 수 없다.  §5-1
```

`미결 (D-s):` R 의 값. **2²² 단위 회신 + ε 별 실제 확장 수 측정 뒤에 정한다.**

`추측:` 포컬 삽입마다 배치 추론 1회 ≈ 0.3 ms 로 보면,
4,194 확장 × 1,000 호출 = 약 **21분/시나리오** (추론만). 밀집 50 × 5 시나리오 ×
§11 4시드 = **약 7시간/곡선 1점**. 기존에 수용한 "50K 조율 스텝 31시간" 과

| **1** | 1단계 승리 조건 3개를 **측정으로 판정** | ①② 가 **구조적 보장**, ③ 만 측정 | 판정의 성격이 바뀐다. **심판이 "보장" 을 받아들이는지 확인이 필요하다** (§5-2) |

| **3** | 탐색 예산 **2²²** | 협상이 라우터를 수백~수천 번 부른다 | **단위를 모르면 R 을 못 정한다** (§5-1) |
| **4** | D-a 수치 합격선 (미결) | "J ≤ +1% 허용 범위" 가 **ε 로 대체**된다 | D-a 의 1번 항목이 성격을 잃는다 |

## 5. skeleton 에 요청할 사항

> V3 는 skeleton 코드를 직접 고치지 않는다 (지시 §3-8).

| | 요청 | 왜 필요한가 | 급함 |
|---|---|---|---|
| **1** | **탐색 예산 2²² 의 단위와 적용 범위** — 시나리오당 / 배관당 / 라우터 호출당? 협상의 **누적** 확장이 예산에 들어가는가? | **D-s 의 반복 상한 R 을 정하는 유일한 입력.** 이것 없이는 협상 설계가 못 닫힌다 | 🚨 **최우선** |
| **2** | **1단계 판정에서 "구조적 보장" 을 받아들이는지** — 포컬 탐색은 `J ≤ (1+ε)J*` 와 성공 수 동일을 **증명으로** 준다. 측정 보고도 함께 내지만, 판정 근거로 보장을 인정하는지 | 1단계 산출물 형태가 달라진다 (측정표 vs 보장 + 확인 측정) | 🚨 높음 |
| **3** | **`중력관 h` · `서포트 u` 의 정의와 접근 방법** (지시 §3-1 입력 특징) | D-p 입력 설계가 막혀 있다. 직접 구현하지 않는다 (D-j·D-o 와 같은 이유) | 높음 |
| **4** | **`support_hint` API 일정** (`form_at`·`groupable`·`together_at`) + **호출 비용** | D-t 끌어당김 항. 칸 단위 빈도라 비용이 설계를 가른다 | 높음 |
| **5** | **리포트에 `Σ 단독 J` 참고 하한 추가** (지시 §3-8). 공유 서포트 단서를 함께 표기 | D-v ② 의 절대 기준 | 보통 |
| **6** | **표현 해상도(R4, 격자 손실 5%) 가 V3 범위인가** — 격자 변형은 계약 §(b) 다. 더 고운 격자나 격자 외 표현이 허용되는가 | D-v ③ 의 두 번째 항이 비어 있다. 범위 밖이면 "조정 이득만" 으로 보고 형태를 줄인다 | 보통 |
| **7** | **확장 수 vs 벽시계 시간** — 1단계 조건이 "확장 수**(시간)** 감소" 로 둘을 묶어 쓴다. 판정은 어느 쪽인가 | 신경망 추론 비용이 **확장 수에는 안 잡히고 시간에는 잡힌다.** 판정 대상이 바뀌면 설계가 바뀐다 | 높음 |
| **8** | **R7 목록** (`docs/reports/r7_cases.md`, 첫 해 / anytime 두 목록) — 기존 요청 유지 | D-t 겨냥 대상 확정 | 보통 |

> **7번은 §5 에서 가장 과소평가되기 쉬운 항목이다.** 확장 수로 판정하면 신경망 ①
> 은 거의 확실히 이긴다 (포컬 정렬이 좋으면 확장이 줄어든다). 벽시계로 판정하면
> **추론 비용이 확장 감소분을 먹을 수 있다** — A\* + octile3d 는 이미 빠르다.
