## 0. 한 줄

**신경망이 경로를 내지 않는다.** 경로는 탐색이 내고, 실현 가능성은 Layer 0 마스크와
확정 단계가 보장한다. 신경망은 두 자리에만 들어간다 — ① 탐색을 **빠르게** 하는
우선순위, ② 다중 배관을 **잘** 놓는 가격·순서·묶음 판단.

이 구조의 가장 큰 효과는 **1단계 승리 조건 3개 중 2개가 학습 결과가 아니라 구조적
보장으로 바뀐다**는 점이다 (§2.3). 대신 새 위험이 하나 생긴다 — **협상 반복이
계약 탐색 예산 2²² 을 먹는다** (§3 D-s, §5-1).

## 1. 판단 근거

> §1 전체는 **소유자 지시 §1 의 요약**이다. V3 가 새로 주장한 것이 아니다.
> 문헌 인용은 지시가 준 것을 그대로 쓰고, V3 가 보탠 것은 출처를 밝힌다.

### 1.1 신경망으로 A\* 를 학습할 수 있는 근거

**근거 — 알고리즘 정렬 (algorithmic alignment).**

| 출처 | 내용 |
|---|---|
| Xu et al. 2020 (ICLR, *What Can Neural Networks Reason About?*) | 망 구조가 대상 알고리즘의 구조와 맞으면 표본 복잡도가 낮아진다 |
| Veličković et al. 2020 (ICLR, *Neural Execution of Graph Algorithms*) | GNN 메시지 전달 1회 = Bellman-Ford 완화 1단계. 층 수가 경로 홉 수 이상이면 최단거리를 **정확히 표현**할 수 있다 |

### 1.2 한계 3가지

| | 한계 | V3 에서 의미하는 것 |
|---|---|---|
| **1** | "표현 가능" 이지 **"학습 보장" 이 아니다.** 고정 깊이 망은 학습보다 긴 경로·큰 맵에서 일반화가 약하다 | **2단계(E2) 의 위험이 바로 이것이다.** 대책은 D-r |
| **2** | 보편 근사 정리가 직접 적용되지 않는다 — 경로는 입력에 대해 **불연속인 이산 출력**이다 | 망이 경로를 직접 내는 설계를 쓰지 않는 이유 |
| **3** | 망이 경로를 직접 내면 **충돌·꺾임·구배·서포트 규칙을 지킨다는 보장이 없다** | §0 의 원칙. 실현 가능성은 탐색·확정이 맡는다 |

### 1.3 핵심 — 1단계에서 품질 우위는 원리적으로 불가능하다

같은 그래프 위에서 **A\* 는 이미 J 최적**이다 (D40). 따라서

```
A* 모방이 주는 이득 = 속도.  품질 이득은 0 이다 (같은 그래프에서는).
```

품질 이득이 나올 자리는 두 곳뿐이고, **둘은 분리해 보고한다** (지시 §1, D-v).

| 출처 | 어디서 | 비고 |
|---|---|---|
| **(a) 다중 배관 조정** | 3단계 | NP-hard 구간. 여기가 본전이다 |
| **(b) 표현 해상도** | 미정 | 격자 손실 약 **5%** (R4 인용). **V3 는 현재 이것에 대한 계획이 없다** → §5-5 |

> ⚠️ **이것이 §7.5 "천장 경고" 를 대체한다.** 1단계를 "A\* 를 얼마나 재현하나" 로
> 본 §7.5 의 서술은 더 약하다. 정확히는 **"A\* 와 같은 품질을 보장받은 상태에서
> 얼마나 빨라지나"** 다. 재현율이 아니라 확장 수가 지표다.

### 1.4 다중 배관 방안 비교

전체 문제(여러 배관을 겹치지 않게 놓으면서 ΣJ 최소)는 **NP-hard** 다
(서로소 경로 문제 계열).

| | 방식 | 성질 | 판정 |
|---|---|---|---|
| **(b)** | **순차 배치**, 앞 배관 = 단단한 장애물 | 항상 실현 가능 · 결정적 | **= skeleton 기준선 (D50).** 이것만 하면 기준선과 같아진다 |
| **(a)** | 각자 최단 경로 → **사후** 간섭 해소 | 기하를 국소적으로 밀어내면 꺾임·서포트 규칙이 **연쇄로 깨진다** | ❌ **쓰지 않는다** |
| **(a′)** | **협상 기반 재라우팅** (PathFinder, 라그랑주 완화) | 간섭 제약을 **가격**으로 완화 | ✅ **채택** |

**(b) 의 약점 — 전부 실측·심판 확인된 것이다.**

- 탐욕이라 **순서에 의존**한다
- 앞 배관이 뒤 배관의 단자·서포트 자리를 막는다 — D59·D90 이후에도 **R7 18건 잔존**
- **랙을 의도적으로 만들지 못한다**
- 밀집 50 완전 성공 **0/5**

**(a′) 협상 루프의 형태**

```
간섭 제약을 가격으로 완화
   ↓
배관별 독립 라우팅 (겹침 허용, 겹친 공간에 가격)
   ↓
붐비는 곳 가격 상승 (현재 혼잡 + 이력 비용)
   ↓
반복
   ↓
마지막에 단단한 장애물로 확정 (= (b) 순차 확정)
```

문헌: PathFinder = McMurchie & Ebeling, FPGA'95, *negotiated congestion* (FPGA 배선).
구조가 거의 같다 — 겹침을 허용하고 가격으로 밀어낸다.

**(a′) 의 이점 — 참고 하한이 생긴다.**

가격 0 일 때 `Σ(배관별 단독 최적 J)` 는 전체 최적의 **참고 하한**이 된다.
기준선 대비 곡선만 보던 것에 **절대 기준**이 하나 붙는다.

> ⚠️ **단서 (지시가 명시):** D 형식 공유 서포트(D81·D82)가 있으면 묶음이 무게를
> 줄이므로 **엄밀한 하한이 아니다.** `Σ 단독 J` 보다 좋은 해가 존재할 수 있다.
> **그 차이가 곧 R7(랙 형성) 이득의 자리다.**

**가장 중요한 한 줄 (지시 §1-2 마지막):**

> 간섭은 **밀어내는 힘**만 준다. **서포트 공유라는 끌어당기는 힘**을 목적에 넣어야
> 랙이 생긴다.

→ 협상만 구현하면 배관이 서로 멀어지기만 한다. 끌어당김 항(D-t)이 없으면
R7 은 안 풀린다.

## 2. 목표 구조

### 2.1 3층

| 층 | 방법 | 학습 역할 | 보장 |
|---|---|---|---|
| **단일 배관 라우터** | **A\* + 포컬 탐색.** admissible `h` 로 `f_min` 유지, `FOCAL = {f ≤ (1+ε)·f_min}` 안을 **학습 점수 순으로** 확장 | **신경망 ①** = 학습 휴리스틱 / 확장 우선순위 | **그래프 위 최적 J × (1+ε) 이하.** 망 품질과 무관하게 하한 유지, 좋으면 빨라짐 |
| **다중 배관 조정** | **(a′) 협상·가격 반복** → 마지막에 **(b) 순차 확정** (단단한 장애물 + 단자·부재 예약) → skeleton 검증기 `Session`(D85 증분)으로 채점 | **신경망 ②** = 가격 갱신 · 순서 · **랙 형성**(어느 배관을 나란히 묶을지) | NP-hard 구간 (R2·R7). 보장 없음 |
| **확정·채점** | **skeleton 검증기** | 없음 | 계약 §(b) — **변경 금지** |

포컬 탐색 문헌: `A*_ε` = Pearl & Kim 1982. 학습된 포컬 우선순위 =
Bhardwaj et al. CoRL 2017 *Learning Heuristic Search via Imitation* 계열.
`추측:` 후자는 기억에 의한 인용이다. 설계에 쓰기 전에 원문 확인이 필요하다.

### 2.2 원칙

```
1. 신경망은 경로를 직접 출력하지 않는다. 실현 가능성은 탐색과 확정이 보장한다.
2. 탐색 중에는 다른 배관을 벌점 붙은 "부드러운 장애물" 로 본다.
   확정 단계에서만 "단단한 장애물" 로 본다.
3. 협상은 라우터를 수백 번 호출한다 — 신경망 ① 의 속도 이득이
   여기서 실제 가치가 된다.
4. D8(GNARL 역할) = "둘 다, 역할 분담" — 단일 경로 쪽은 속도, 조정 쪽은 품질.
```

### 2.3 이 구조가 걷어내는 기존 실패 위험

> ⚠️ **2026-10-21 정정 (소유자 회신 3).** 아래 표의 초판은 "조건 2개가 구조적 보장이
> 된다" 고 적었다. **과장이었다.** 보장은 **라우터 비용** 기준이고 **계약 판정은 검증기 J**
> 다. 수정판은 아래와 같고, 소유자 판정은 **"구조적 보장은 근거로 인정, 판정은 측정"** 이다.

| 계약 §(e2) 1단계 조건 | 포컬 탐색이 주는 것 | 왜 판정은 측정인가 |
|---|---|---|
| **J ≤ A\* +1%** | **라우터 비용** ≤ (1+ε) × 그 표현 위 최적 — ε=0.01 로 증명된다 | 라우터 비용 = 직관 + 엘보 + **추정 서포트(D57, 엣지 중점 근사 D80 ⑨)**. **계약 J 는 검증기 값**이고 둘의 어긋남이 크다 — D57 오차 중앙 **+18.6%**, D75 에서 라우터 비용으로 거른 후보의 **51%(20/39)가 검증으로 기각**됐다 |
| **성공 수 같음** | `FOCAL ⊆ OPEN`·가지치기 없음 → **같은 예산이 무한하면** 완전성이 A\* 와 같다 | 예산이 유한하다 (D73 2²²). **확장 순서가 다르면 예산 소진 시점이 다르다** — 포컬이 먼저 끝낼 수도, 먼저 소진할 수도 있다 |
| **확장 수(시간) 감소** | 없음 — **학습 결과** | ← 원래부터 측정이다 |

→ **E1 에서 셋 다 측정한다.** 보장은 "왜 J 가 크게 나빠질 수 없는가" 의 **근거**로 보고하고,
합격·불합격은 측정값으로 가른다.

`미결:` 라우터 비용 ↔ 검증기 J 의 어긋남이 ε 보장을 얼마나 희석하는지. **1단계에서
ε 별로 두 값을 함께 재면 바로 나온다** — 이것이 1단계의 부수 산출물 중 가장 쓸모 있다.

**RL 병리 4건이 1·2단계에서 사라진다** — 1단계에 MDP 가 없기 때문이다.

| 기존 Lock / 경고 | 이 구조에서 |
|---|---|
| **S1-L1** 1단계 수렴 붕괴 (0.271 → 0.00) | **적용 안 됨.** PPO 가 없다 |
| **τ 붕괴** (§19-2) | **적용 안 됨.** softmin 샘플링이 없다. τ 는 3단계로 (S1-N1 그대로) |
| **h 드리프트** (§19-2) | **적용 안 됨.** h 는 지도 회귀로만 학습·고정된다 |
| **G3-L1 수렴 천장 0.40~0.45** | **적용 안 됨.** "목표에 닿는가" 는 A\* 가 보장한다. 천장은 *도달률* 의 천장이었다 |
| **데드락** (§4 STAY, §16-5 `fail_cost`, 종단 처리) | **실패 양식이 아니다.** A\* 에서 막다른 길은 닫힌 노드이고 탐색이 되돌아간다 |
| **G3-N7** 벤딩 마스크가 탐색 장치 | **1·2단계에서 무의미.** 체계적 탐색에는 탐색 보조가 필요 없다. 마스크는 후계자 생성에서 Layer 0 으로만 작동 |

> ⚠️ **이 표는 "쉬워졌다" 는 뜻이 아니다.** 위험이 **옮겨간** 것이다.
> 새 위험은 §7 에 모았고, 그중 **확장 예산(D-s)** 이 가장 크다.

```
협상 1회 = 배관 수 × 라우터 호출.  밀집 50 · R 반복이면 50R 회.
벽시계로 재므로 호출당 (탐색 + 추론) 시간이 그대로 R 의 상한을 정한다.
```

## 4. 충돌 목록 — 기존 V3 결정과 어긋나는 것

> 기존 문서를 그대로 둔다.

### 4-1. ★ 진짜 GNARL 구조 (§6) — 런타임이 다르다

| | 기존 §6 | 이 설계 |
|---|---|---|
| 경로를 내는 주체 | **정책** (`softmin(-f/τ)` 샘플링, MDP 전개) | **A\* 포컬 탐색** |
| 신경망의 자리 | `f = g + ΔJ + h` 의 `h` — 행동을 **직접 고른다** | `f_min` 은 admissible h, **학습 h 는 FOCAL 안의 정렬** |
| 되돌아가기 | 없다 (한 방향 전개, 막히면 데드락) | **있다** (OPEN 유지) |
| 실패 양식 | 데드락 · 타임아웃 | **없다** (완전성이 A\* 와 같다) |

**충돌의 성질:** §6 은 **기각이 아니라 역할 변경**이다. `h_net`·배치 평가·J 정규화는
전부 승계되고, 없어지는 것은 **MDP 전개층**(τ, softmin, PBS, 종단 처리)이다.

`미결:` §6 의 서술을 어떻게 고칠지. **기존 §6 은 G3 실측의 기록이므로 지우지 말고,
"1·2단계는 포컬 탐색을 쓴다 / §6 의 MDP 전개는 3단계 후보" 로 범위를 다는 것을 권고**한다.

## 10. `h` 의 느슨함과 ε 보장의 정확한 의미 (2026-10-22)

### 10.1 skeleton D92 / D108 — 서포트 하한은 0 뿐이다

skeleton 이 **"남은 서포트 비용의 admissible·consistent 하한"** 을 시도했고 결과는:

```
일관성(consistency)을 유지하는 하한은 0 뿐이다.
  · 표 범위 밖 구간은 라우터 서포트 비용이 0 이다
  · 서포트 가능 엣지가 10 mm 까지 짧을 수 있다
→ 확장 수 감소 0% 로 기각 (D108)
```

따라서 `f_min` 에 쓰는 `h`(D41 = 남은 유클리드 × kg/m + 최소 꺾임 × e45)는

| 못 보는 것 | 크기 |
|---|---|
| **추정 서포트 비용** (D57) | 기본 세트 라우터 비용의 약 **9%** |
| **중력관 계단 비용** (D61~D63) | T5 는 꺾임 수 **+37~51%** (S1-2) |

→ **`f_min` 이 실제 비용보다 체계적으로 낮다.** 그 느슨함을 측정한 것이 §10.6 이다.

### 10.2 ⚠️ 보장의 방향을 짚어둔다 — 보장은 약해지지 않는다

소유자 메모는 *"포컬 보장의 기준(f_min)은 그대로 약하다. ε 는 '약한 하한 대비 (1+ε)'
라는 점을 기억할 것"* 이다. 실무 함의는 맞는데, 그대로 읽으면 **보장이 약해진다**로
오해될 수 있어 수식으로 확인했다.

```
① h 가 admissible 이면, 최적 목표를 꺾기 전 OPEN 에는
   최적 경로 위 노드가 있고 그 f ≤ C*        →  f_min ≤ C*  (항상)
② 목표를 FOCAL 에서 꺾을 때
   g(목표) = f(목표) ≤ (1+ε)·f_min ≤ (1+ε)·C*
```

→ **보장은 `C*` 대비 `(1+ε)` 이고, `h` 가 느슨해도 변하지 않는다.**

그리고 **방향이 반대다.** 매 시점 허용 폭은 `ε·f_min` 이고 `f_min ≤ C*` 이므로

```
ε·f_min  ≤  ε·C*
h 가 느슨할수록 f_min 이 낮고 → 허용 폭이 kg 기준으로 더 좁다
```

즉 *"약한 하한 대비"* 는 **"보장이 약하다"** 가 아니라 **"우리가 실제로 쓰는 자유가
ε 가 암시하는 것보다 적다"** 는 뜻이다. 보장은 그만큼 **보수적**이다.

`미결:` 좁아짐이 실제로 얼마인지는 탐색 중 `C*/f_min` 분포가 필요하다 —
`v3/measure_focal.py` 에 `f_min` 보존을 넣었고 **재측정 대기**다 (§11).

### 10.3 그래서 `h` 가 느슨한 것의 실제 손해는 둘이다

| | 손해 | 누가 받나 |
|---|---|---|
| **1** | **A\* 가 느려진다** — 확장 수가 늘어난다 | **기준선도 똑같이 받는다** → 여기가 신경망 ① 의 기회 |
| **2** | **같은 ε 로 얻는 자유도가 줄어든다** (`ε·f_min` 이 좁다) | V3 만 받는다 |

품질은 어느 쪽에도 없다. **h 의 느슨함은 품질 위험이 아니다.**

### 10.4 🔒 `f_min` 은 구조적으로 개선할 수 없다 — 그게 설계다

*"학습 `ĥ` 로 `f_min` 을 올리면 되지 않나"* — **안 된다.** 포컬 탐색의 구조가 그렇다.

```
OPEN  정렬 = f = g + h_admissible      ← 보장이 여기서 나온다
FOCAL 정렬 = 학습 점수 ĥ               ← 망은 여기만 건드린다
```

학습 `ĥ` 는 **`f_min` 계산에 들어가지 않는다.** 넣으면 admissible 이 깨지고 `(1+ε)` 보장이
사라진다. `h` 를 개선하려면 **증명 가능한** 하한이 필요하고, **D92 가 그 길을 닫았다**
(서포트 하한 = 0).

→ **`f_min` 은 약한 채로 남는 것이 이 설계의 전제다.** 약점이 아니라 분업이다.

측정 장치가 심판과 같은 값을 낸다는 확인이다 (등가성 시험 §6.2 와 같은 계열).
**우리가 더 쪼갠 것** — skeleton 보고에 없는 분해:

| 단독 실패 | n | T5 중력관 | T1 압력관 | 구경 분포 |
|---|---|---|---|---|
| 경로 없음 | 23 | **18 (78 %)** | 5 | 15A 3 · 25A 2 · 50A 2 · 65A 2 · 100A 1 · 150A 1 · 200A 1 · 300A 2 · 400A 3 · 500A 5 |
| 상한 소진 | 12 | 4 | **8 (67 %)** | 500A 4 · 100A 3 · 300A 1 · 150A 1 · 65A 1 · 50A 1 · 15A 1 |

→ **두 덩어리의 성격이 다르다.** 경로 없음은 **중력관 표현력**(R5)이 지배하고,
상한 소진은 **압력관·대구경 탐색 비용**이 지배한다. 전자는 D102(표현), 후자는
1단계(속도)다. **섞어서 "35건" 으로 보고하면 어느 쪽에 투자할지 안 보인다.**

### 13.5 그래서 D-t 의 우선순위는 — **올라간다, 단 근거가 바뀐다**

| | 바뀐 전 근거 | 2026-10-27 근거 |

| **D-t (끌어당김·랙)** | "R7 18건을 겨냥한다" | **"Σ 단독 J 아래로 내려가는 유일한 길."** 공유 서포트는 **현재 0건** — 기준선이 한 번도 만들지 못했다. R7 막힘 해소(1·5건)는 부산물 |

(§10.6) 이므로 **랙이 형성되면 그 몫이 공유로 줄어든다** — 1 % 천장과 자릿수가 다르다.

⚠️ **그러나 크기는 아직 미측정이다.** 공유로 얼마나 줄어드는지는 `support_hint`
(D100, **S1-7b**) 가 나와야 센다. **1 % 보다 크다는 것은 `추측:` 이고 측정으로 확인한다.**
`미결 (D-t):` 묶임 가능 쌍의 빈도 — 기본 세트에서 나란히 갈 수 있는 수평 평행 쌍이

## 14. 🔧 서포트 학습 감시 (2026-10-28 소유자 지시)

소유자 우려: **서포트 J 는 배관 J 보다 학습이 늦을 수 있다** — 신호가 계단형(형식 전환·
간격 개수)이고, 앞뒤 구간과 다른 배관에 좌우되고(부재 막힘·묶음), 비중이 평균 약 9% 로
작지만 편차가 크다. 지시 4건을 아래에 반영한다.

**우리 측정이 이 우려를 뒷받침한다.** §10.6: 서포트 비중 라우트별 중앙 **9.4%** 인데
분포가 **15A 34.5% ~ 300A 5.1%** 로 벌어지고, **서포트 비중 ↔ `h` 느슨함 r = 0.657** 이다.
즉 **`ĥ` 가 메워야 하는 `h` 의 맹점이 상당 부분 서포트**다 (§10.5). 서포트 머리가 안
배우면 **신경망 ① 이 할 일의 핵심이 비는 것**이다.

### 14.1 ① 보상·라벨에서 서포트 항을 분리한다 — **머리를 둘로**

**구조:** `ĥ` 를 두 머리로 낸다. `ĥ = ĥ_pipe + ĥ_sup` (kg).

| 머리 | 라벨 | 근거 |
|---|---|---|
| `ĥ_pipe` | 남은 **직관 + 엘보** (+ 관통 D95) | 매끄럽고 거리에 거의 비례 — 쉬운 쪽 |
| `ĥ_sup` | 남은 **추정 서포트** | 계단형이고 `h` 가 전혀 못 보는 쪽 (D92·D108 하한 0) |

**라벨은 이미 분해 가능하다** — 확인했다: skeleton `LayeredGraph` 가 엣지별
`support_cost(a,b)` · `penetration_cost(a,b)` 를 따로 내고 `cost(a,b)` 가 그 합이다
(`layered.py` 1105·1109·1113). A\* 최적 경로의 **뒤에서부터 누적**하면 상태마다
`(남은 pipe+elbow, 남은 support, 남은 penetration)` 가 정확히 나온다. 추가 계산 없다.

⚠️ **합은 kg 로 유지한다.** FOCAL 순서는 `ĥ = ĥ_pipe + ĥ_sup` 으로 매긴다 — 정규화는
**손실 안에서만** 한다 (§14.3). 머리를 나누는 것은 **학습 신호 분리**이고 탐색에 쓰는
값은 하나다.

**3단계 보상도 같은 원칙:** `verifier.Session` 의 J 분해에서 `support` 를 **합계와 별도로**
받는다 (출력 `routes[].J.support` · `global.J_breakdown`). 보상은 D77 사전식이 정본이고,
서포트 항은 **진단·가중용**이다 — 배관별 `kg_share` 를 배관별 보상으로 쓰지 않는다는
기존 결론(§13.1 보상 설계)은 그대로다.

### 14.2 ② `form_at` 을 **탐색 중에는 부르지 않는다** — 비용 계산

S1-7b 가 병합됐고 비용이 측정됐다 (`docs/verifier_api.md` §4): `form_at` 중앙
**0.84~2.45 ms** (p90 4.91 · 최대 9.6), 힌트 객체 생성 1~31 ms.

```
기준선 확장 중앙 272,922 (2²², §10.6) · skeleton A* 약 28,000 확장/초 → 라우트 약 10 초
확장마다 form_at 1회 = 272,922 × 1.35 ms ≈ 368 초 = 기준선의 약 37배
```

→ **벽시계 판정(D98) 아래에서 노드마다 부르는 설계는 성립하지 않는다.** 2배 속도 이득을
노린다면 라우트 예산이 약 5초이고, 그 **10% 를 힌트에 쓴다 해도 라우트당 약 370회**가
한도다. 반면 기본 세트 서포트 수는 배관당 약 **8.6개**(1,770/205)다.

| 쓰는 곳 | 호출 규모 | 판정 |
|---|---|---|
| **탐색 루프 안 (노드·FOCAL 후보마다)** | 10⁵~10⁶ | ❌ **금지** — 벽시계가 37배 된다 |
| **라벨 생성 (오프라인)** | 제한 없음 | ✅ **쓴다** — 곡선 시간 밖 (§14.5) |
| **라우트당 거친 표본** (단자·첫 꺾임 선·띠 경계 수백 점, 구경별 캐시) | 10²~10³ | 🔸 **후보** — 예산의 5~10%, 이득 측정 후 결정 |
| **3단계 D-t** (협상 반복 × 배관 × 후보 몇 개) | 10²~10³ | ✅ 적합 |

**그리고 1단계에서는 `form_at` 이 더할 정보가 거의 없다.** 라우터는 이미 엣지별 서포트
비용과 상태 `u` 를 **구경별 캐시**로 들고 있다 (D80 ⑨, `State.su`). `form_at` 과의 차이는
세 가지뿐인데 ① 다른 놓인 배관의 막힘 ② D 묶음 — **둘 다 단일 배관엔 없다** ③ 엣지 중점
근사 (**M29**). 그래서 **1단계 입력 특징은 라우터 캐시에서 뽑는다**:

```
현재 u (= State.su, 마지막 서포트 가능 지점 이후 정규화 길이, ≤ 1)
다음 엣지들의 서포트 비용 (support_cost — 이미 캐시)
가장 가까운 지지면까지 거리 · 표 범위 밖 여부 (LineSupport 가 들고 있다)
중력관 h (D61~D63, State.hz)
```
D-p 의 "서포트 맥락·중력관 `h` 는 요건" (§10.5) 이 이것으로 구체화된다. **신규 채널은
이 네 가지이고, `form_at` 호출은 들어가지 않는다.**

### 14.3 ③ 서포트 항이 묻히지 않게 — 정규화 2머리 + **순위 지표**

단일 머리로 `ĥ` 전체를 회귀하면 서포트는 **기울기의 8~9% 밖에 차지하지 않는다**
(합계 비중 8.2%, §10.6) — 소유자 우려가 바로 이 산수다.

```
손실 = w_p · L(ĥ_pipe / s_p , y_pipe / s_p) + w_s · L(ĥ_sup / s_s , y_sup / s_s)
s_p, s_s = 각 성분의 세트 수준 척도 (성분별 표준편차 — 라우트 C* 가 아니라 성분별로)
기본 w_p = w_s = 1  →  서포트가 8% 가 아니라 **절반**의 기울기를 받는다
```

`미결:` `w_s` 를 1보다 올릴지는 **측정 후**다. 올리면 `ĥ_pipe` 가 나빠질 수 있고,
FOCAL 순서는 **합**으로 매기므로 둘의 균형이 곧 순서 품질이다.

🔸 **MAE 보다 중요한 지표 — 순위.** §9 의 결론이 "띠 안 순서가 전부" 이므로 보고 지표에
**순위 일치**를 넣는다: 각 확장 시점에서 **A\* 최적 경로의 다음 상태를 FOCAL 안에서 몇
번째로 꼽는가** (top-1 일치율 · 평균 순위). 이것을 **서포트 비중 밴드별**로 쪼갠다 —
서포트 머리가 작동하면 **비중 높은 밴드에서 순위가 더 개선**돼야 한다. 그게 안 되면
서포트 학습이 실패한 것이고, MAE 만 보면 그 실패가 안 보인다.

### 14.4 ④ 학습 곡선을 나눠 기록한다 + **정체 보고 기준**

`step1_train.ipynb` §17 계기판에 계열을 추가한다 (§17-2 에 패널 신설):

| 기록 | 왜 |

짝지은 비교 + 산포를 함께 낸다.

### 14.5 🆕 M29 가 여는 길 — **1단계에서도 J 이득이 가능할 수 있다** (`추측:`)

지금까지 "1단계 J 우위는 원리적으로 불가능" 이라고 적어 왔다. 근거는 *"A\* 는 그 그래프
위 J 최적"* (D40). **그런데 A\* 가 최적인 것은 라우터 비용이고, 판정은 검증기 J 다.**

| | 최소화하는 값 | 판정 |
|---|---|---|
| 기준선 A\* | 직관 + 엘보 + **추정** 서포트 (D80 ⑨, 엣지 중점 근사) | — |
| 심판 | 직관 + 엘보 + **검증기** 서포트 (D80 ③④⑤ 탐욕 배치) | ✅ |

**세 가지 측정이 이 간극이 결정을 바꿀 만큼 크다고 말한다:**

| 근거 | 수치 |
|---|---|
| **M29** (skeleton, 2026-10-27) | 라우터 추정이 **짧은 수직·45° 구간의 무거운 서포트를 과소평가**한다 — 기록·크기 측정은 E1 에서 |
| **D75** | 라우터 비용으로 고른 개선 후보의 **51%** 를 검증기가 기각했다 (S1-5b) |
| **§9.1** (우리) | FOCAL ε=0.01 띠 안에 **중앙 3,643개** 상태 — 라우터 비용이 1% 안에서 같은 경로가 수천 개 |

→ **띠 안에서 "라우터 비용은 같아 보이는데 검증기 J 는 다른" 경로들이 공존한다.**
`ĥ_sup` 이 **검증기 등급**(= `form_at` 라벨)으로 학습되면 그중 가벼운 쪽을 고를 수 있다.
이것은 A\* 를 자기 목적함수에서 이기는 것이 **아니다** — **프록시와 심판의 간극을 쓰는
것**이고, ε 보장은 라우터 비용에 걸려 있어 **깨지지 않는다** (`g ≤ (1+ε)C*_라우터`).

⚠️ **아직 `추측:` 이다. 크기를 모른다.** 측정 설계를 먼저 둔다:

```
표본 라우트 N개 × 포컬 탐색 ε=0.01 을 서로 다른 무작위 priority 시드 K개로 돌린다
 → 띠 안의 서로 다른 경로 K개 (전부 라우터 비용 ≤ (1+ε)C*)
 → 각각 skeleton 검증기로 단독 채점
 → 같은 띠 안 검증기 J 의 산포 = 1단계가 J 에서 벌 수 있는 상한의 추정
```
싸다 — 라벨 생성과 같은 장치로 돌아가고 **곡선 시간 밖**이다. `미결:` N·K (초안 N=30 ·
K=8). **이 산포가 D101 의 1% 천장과 비교되는 숫자다** — 크면 1단계의 가치가 속도만이
아니게 되고, 작으면 지금 설명대로 속도뿐이다. **둘 중 어느 쪽이든 측정으로 적는다.**

🔸 **단 1단계 승리 조건은 그대로 `J ≤ +1%`(상한)이다.** J 이득은 승리 조건이 아니라
**부수 이득**으로 보고한다 (D102 분리 보고 원칙과 같은 자리).

## 15. 🔴 1단계 추론 예산 — **벽시계 판정은 포컬 탐색을 컴파일해야 성립한다** (2026-10-28)

라벨 생성을 시작하면서 **판정식에 숫자를 넣어 봤고, 가장 큰 설계 제약이 여기서 나왔다.**
§7 에 "최대 위험 = 추론 비용이 확장 감소분을 먹는 것" 으로 적어 둔 것의 **실측판**이다.

### 15.1 실측 — 확장 1회의 단가

같은 기본 세트·같은 비공개 표·같은 `e154ee9` 에서 **이미 가진 원자료**로 계산했다.

| 구현 | 확장당 벽시계 | 출처 |
|---|---|---|
| **skeleton A\*** (numba, 기준선) | **5.37 µs** | `out/h_slack_priv.jsonl` · ok · 확장 > 5,000 · n = 161 중앙 |
| **V3 포컬 탐색** (파이썬, ε=0 · priority 없음) | **61.9 µs** | `out/focal_basic_priv.jsonl` · ok · 확장 > 500 · n = 94 중앙 |

**11.5 배**다. 그리고 이 61.9 µs 는 **포컬의 싼 경로**다 — ε=0·priority 없음이라
`heappop` 만 쓴다. ε>0 + priority 를 켜면 현재 구현은 확장마다 **OPEN 전체를 훑어**
FOCAL 멤버를 고른다 (`v3/focal.py` 의 `for i, (f, _, g, s) in enumerate(open_heap)`).
viable OPEN 중앙이 18,327 이므로 (§9.1) **확장 1회에 priority 평가가 1.8만 번**이다.
→ **지금 구현으로는 벽시계 측정 자체가 성립하지 않는다.** 이중 큐(OPEN = f 순 힙,
FOCAL = priority 순 힙, `f_min` 이 오를 때만 지연 재동기)로 바꿔야 한다.

### 15.2 손익분기 — 필요한 확장 감소 배수 `R`

`T_기준 = E·c_b`, `T_V3 = (E/R)·(c_s + b·c_h)` (b = 확장당 생성 상태 수, 유효 5~10).
`R > (c_s + b·c_h) / c_b`, `c_b = 5.37 µs`.

| 조합 | `c_s` | `b·c_h` | 필요 `R` | 판정 |
|---|---|---|---|---|
| 파이썬 포컬 + torch `ĥ` (hidden 256) | ~70 µs | ~100 µs (배치 1회/확장) | **> 32** | ❌ 비현실 |
| 파이썬 포컬 + 작은 `ĥ` | ~70 µs | ~15 µs | **> 16** | ❌ |
| **컴파일 포컬 + 컴파일 `ĥ` (hidden 32)** | ~7 µs | ~13 µs | **> 3.7** | 🟡 가능선 |
| 컴파일 포컬 + **선형 `ĥ`** | ~7 µs | ~0.6 µs | **> 1.5** | ✅ 여유 |

`c_h` 는 FLOPs 로 추정했다 — hidden 32·depth 2 = 약 3.3k FLOPs/상태, 단일 코어
약 2 GFLOP/s → 1.7 µs. hidden 256·depth 3 = 약 150k FLOPs = 75 µs **상태당**이라
확장당 b 배가 되면 기준선 전체 예산을 혼자 먹는다.

### 15.3 결론 3개 — 설계가 바뀐다

1. **컴파일 포컬 탐색이 1단계 벽시계 조건의 선행 조건이다.** 파이썬 구현으로는
   품질이 완벽해도(오라클이어도) 측정이 의미를 갖지 못한다. → §11 멈춘 작업에
   **`v3/focal_fast.py` (이중 큐 + numba)** 를 추가한다.
2. **`ĥ` 의 크기가 산수로 묶인다.** D-p 는 "76차원 기반 MLP" 까지만 정했고 폭·깊이를
   비워 뒀는데, **hidden ≤ 32~64 가 상한**이다. `미결:` 그 크기로 순위 품질이
   충분한가 — **큰 망(품질 천장)과 작은 망(배포 가능)을 둘 다 학습해 격차를 보고한다.**
   격차가 작으면 그대로 가고, 크면 선형·GBDT 같은 더 싼 형태나 **상태당 1회 캐시**
   (priority 는 상태만의 함수이므로 생성 시 1회 계산해 큐에 실어 둘 수 있다)로 간다.
3. **확장 수 감소가 "보조 진단" 이지만 학습이 직접 움직이는 유일한 양이다** (D98).
   그래서 1단계 보고는 **① 확장 감소 배수 `R`(학습 품질) ② 구현 단가 `c_s`·`c_h`
   (엔지니어링) ③ 둘의 곱인 벽시계**를 **분리해서** 낸다. 섞으면 "학습이 안 됐는지
   구현이 느린지" 를 구분할 수 없다 — v2 에서 배선 버그 3건이 "조용히 통과" 한 것과
   같은 계열의 실수다.

🔸 **`R` 의 상한은 크다.** 오라클이면 경로 위 상태만 확장하므로 50 안쪽 = 기준선
272,922 대비 **5,000배**다. 즉 `R > 3.7` 은 품질 요구로는 낮은 편이고, 문제는
**어디까지 실제로 되는가**다. 그 수치가 1단계의 첫 실측 결과가 된다.

### 16.1 설계 선택 3건과 근거

**① `h` 위의 비음수 잔차를 배운다.** `h`(D41) 가 admissible 이라 `rem_pe ≥ h` 가 항상
참이다 (라벨 생성에서 **매 상태 검사**하고 어긋나면 기록한다 — 지금까지 위반 0). softplus
로 비음수를 강제하면 `ĥ ≥ h` 가 보장되고, 망은 **`h` 가 못 보는 부분에만** 용량을 쓴다.

**② 라벨은 최적 경로 위 상태뿐이다 — 한계를 그대로 적는다.** 포컬 탐색이 점수를 매기는
대상은 FOCAL 안 전선 상태이고 그 대부분은 경로 밖이다. 경로 밖 `rem` 을 정확히 받으려면
상태마다 A\* 를 다시 돌려야 해서(상태당 수 초 × 수만 상태) 비용이 맞지 않는다.
→ **"경로 밖에서도 순서를 맞추는가" 는 가정이 아니라 측정 대상**이고, 그래서 주 지표를
MAE 가 아니라 **순위 일치율**로 뒀다 (§14.3). 학습 중에는 같은 라우트의 경로 위 상태 쌍으로
대리 지표를 재고, 진짜 FOCAL 순위는 `measure_stage1` 이 탐색을 돌려 잰다.

**③ `ends` 4채널은 학습셋에서 상수다 (실측).** 최적 경로 위 상태는 `ends = 15`
(네 꺾임 등급 모두 허용)뿐이었다. 탐색 중 FOCAL 멤버는 제한된 마스크를 가질 수 있으므로
**채널은 남겨 두지만**(나중에 더하면 freeze + zero-padding 충돌, D-n §2.1) **학습되지
않는다** — 추론 때 값이 변하면 외삽이다. 정직하게 기록하고, 학습 로그가 상수 채널을
경고로 출력한다.

### 16.2 운영에서 걸린 것 — 기록

* **skeleton 고정층 LRU(`_FIXED`)가 단일 블록 층을 쌓기만 한다.** 시나리오를 넘어갈 때
  `clear_cache()` 를 부르지 않으면 RSS 가 단조 증가해 OOM 으로 죽는다 (실측: 약 60
  라우트에 3.4 GB). 라벨·특징 양쪽에 시나리오 경계 비우기를 넣었다.
* **라벨 생성은 OOM 을 전제로 짰다.** 라우트 단위 `.jsonl` 증분 기록 + 시도 표시
  (`.attempt`) + 바깥 재시작 루프 — 죽은 라우트는 `status="oom_killed"` 로 남고
  나머지는 보존된다 (h 느슨함 측정에서 쓴 장치와 같다).
* **생성기 결정성 확인.** 평가 시드 20261008 로 다시 생성한 시나리오가 저장된
  `proc_000.json` 과 장애물 27개·배관 10개·구경·단자 좌표까지 **전부 일치**했다.
  → 학습 시드 시나리오가 평가 분포와 **같은 생성 설정**임이 보장된다 (라우팅은 하지 않고
  기하만 비교 — 평가 시드를 학습에 쓰지 않는다, D110 ⑤).

## 17. 1단계 파일럿 실측 (2026-10-28) — **통과 수는 이겼고 벽시계는 졌다**

학습 시드 라벨 223 라우트(12,763 상태)로 `ĥ` 를 학습하고 **검증 시드**
40000000~40000001 의 20 라우트로 쟀다. 양쪽 같은 그래프·같은 확장 예산 400,000.

### 17.1 결과

| | 기준선 A\* (numba) | V3 포컬 ε=0.01 (`ĥ` priority) |
|---|---|---|
| **푼 라우트 (20 중)** | **7** | **11** |
| 확장 감소 `R` (짝지은 7) | — | 중앙 **1.37** (범위 1.06~2.43) |
| J 비 (라우터 비용) | 1.0 | 중앙 **1.000** · **최대 1.00134** |
| 벽시계 합 (짝지은 7) | 3.77 s | 66.25 s |
| priority 호출 단가 `c_h` | — | **92.9 µs** |

**① 통과 수는 이미 이겼다 (D77 ②).** 같은 예산에서 11 대 7 이고 **4 라우트가
기준선 `timeout` → V3 `ok`** 로 뒤집혔다. J 는 최악 **+0.134%** 로 승리 조건
`J ≤ +1%` 안에 한참 들어온다. 🔸 **이 이득은 순위 품질에서 온 것이 아니다** —
`R` 이 1.37 뿐인데도 뒤집혔다. 기전은 **ε 띠 자체**다: 최적을 증명하지 않고
(1+ε) 안의 경로를 받아들이면 같은 깊이에서 해를 **더 일찍 확정**한다.
D101 이 말한 "1단계 속도가 D77 ② 로 환전된다" 의 실측이고, 환전 경로가
**속도가 아니라 준최적 허용**이라는 점이 새로 밝혀진 것이다.

**② 벽시계는 17.6배 졌다.** §15 가 예고한 그대로다.

### 17.2 🔴 §15 의 비용 귀속이 틀렸다 — 정정한다

§15 표는 `c_h` 를 **신경망 FLOPs** 로 추정해 hidden 32 에 약 1.7 µs 를 잡았다.
실측 `c_h` 는 **92.9 µs** 다. 망 자체는 3,363 파라미터 · 6,592 FLOPs/상태라
FLOPs 추정이 맞다면 3 µs 대여야 한다.

→ **비용의 주범은 추론이 아니라 파이썬 특징 생성**이다 (`features.FeatureMaker.one`
이 상태마다 68차원 벡터를 파이썬으로 조립한다). 즉 **망을 더 줄여도 거의 안 빨라진다.**

**우선순위가 바뀐다.**

| | 바꿀 것 | 예상 효과 |
|---|---|---|
| 1 | **특징 생성을 컴파일·증분화** — 상태 전이에서 바뀌는 성분만 갱신 (대부분 채널은 부모 상태와 같다) | `c_h` 92.9 µs 의 대부분 |
| 2 | 포컬 탐색 컴파일 (§15) | 확장당 62 µs |
| 3 | 망 축소 | 3 µs 대 — **거의 의미 없다** |

§15.2 의 "필요 `R`" 표는 **`c_h` 를 FLOPs 로 잡은 값이라 신뢰하지 않는다.**
실측으로 다시 쓰면 지금 조합은 `(62 + 92.9·b)/5.37` 로 `b`(확장당 생성 상태)가
5 면 **필요 `R` ≈ 98** 이다. 1·2번을 하지 않으면 **`R` 로는 도달 불가**다.

### 17.3 비용 쪽 순위 지표는 포화돼 있었다 — 지표를 바꿨다

학습 중 대리 지표(같은 경로 위 상태 쌍의 순서 일치)가 `h` 단독 **0.966** vs
학습 `ĥ` **0.947** 로 **학습이 더 나빴다.** 원인은 모형이 아니라 지표다 — 같은
최적 경로 위에서는 남은 비용이 단조 감소하고 `h` 가 이미 그것을 거의 맞춘다.
**질문에 맞지 않는 지표**였다.

→ **`d̂`(남은 홉 수) 머리를 추가했다.** `ĥ` 는 **비용**이고 확장 수를 줄이는 것은
**거리**다 (유계 준최적 탐색의 h vs d — Speedy search · EES). ε 보장은 OPEN 의
admissible `h` 에 걸려 있어 **priority 를 바꿔도 깨지지 않는다.**
홉 순위 일치율은 **포화되지 않았다**: 0.719 → **0.921** (MAE_hops 30.6 → 9.8,
홉 중앙 28). 이 지표로 priority 를 바꾼 측정이 진행 중이다.

### 17.4 서포트 머리 — 소유자 우려가 1차 런부터 재현됐다

**정체 기준이 실제로 발동했다** (2머리 런 ep 12·19, 3머리 런 ep 9·12·19):
`MAE_sup/s_s` 가 3회 연속 상대 2% 미개선인데 `MAE_pipe` 는 개선 중.

🔻 **그리고 머리를 셋으로 늘리면 서포트가 더 나빠졌다** — `MAE_sup` 83.8 → **93.4**
(같은 데이터·같은 폭). 공유 몸통이 32 유닛뿐이라 세 목표가 용량을 다툰다.
**`d̂` 가 서포트를 밀어낸다.**

→ 대응 후보 (측정 후 결정, `미결:`): ① 몸통 분리 (서포트 전용 몸통) ② `w_sup > 1`
③ 폭 확대 — 단 **③ 은 §17.2 로 값이 싸졌다** (비용 주범이 망이 아니므로 폭을
늘려도 벽시계가 거의 안 변한다). **지금은 ③ 이 가장 유력하다** — §15 가 금지했던
선택지가 비용 귀속 정정으로 열렸다.

**구경별·밴드별 (2머리 런, 검증 1,906 상태):** `MAE_sup` 는 서포트 비중 밴드에서
**단조가 아니다** — 0~3% 47.3 · 3~9% 46.8 · 9~20% 64.2 · 20~30% **22.8** ·
30%+ **100.1**. "비중 높은 밴드에서 더 개선된다" 는 §14.3 의 반증 가능한 예측은
**지금 데이터로는 성립하지 않는다.** 30%+ 밴드(소구경 15A 쪽)가 가장 나쁘다.
`미결:` 라벨 223 라우트로는 밴드별 표본이 얇다 — 전체 라벨로 다시 본다.
